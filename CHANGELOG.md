# Changelog

## 1.5.0 - 2026-10-29

Agent- and model-neutral skill (docs/agents.md).

Added
- `SKILL.md` follows the open Agent Skills specification: `compatibility` and `metadata.version` fields, no vendor-specific wording.
  - A capability table tells any agent what to do with a shell, MCP tools, files only, or chat only.
  - The kit and the references are located by layout (package or repository).
- `agents/openai.yaml` sidecar (display metadata and invocation policy for OpenAI Codex/ChatGPT); other agents ignore it.
- `watchover build-skill` (`scripts/akl_skill.py`) builds the Agent Skills package and a prompt pack for assistants without skill support: full system prompt, short system prompt and knowledge files.
- `watchover install-skill --agent claude|codex|copilot|cursor|gemini|agents|custom [--scope project|user]` installs the skill in each agent's skills folder.
- `watchover validate-skill` checks a skill folder against the specification: fields, limits, name = folder, body length, referenced files. CI validates the source and the built package.
- `watchover mcp` (`scripts/watchover_mcp.py`) is a dependency-free MCP stdio server.
  - Tools: every kit command, with arguments generated from its options. Commands that call Akeyless are opt-in with `--live`.
  - Resources: `SKILL.md`, the docs and the YAML model.
  - Prompts: one per skill command.
- `AGENTS.md` (with `CLAUDE.md` / `GEMINI.md` importing it) for AI coding agents working on the repository.
- Manual: new chapter "Using akeyless-watchover with any AI agent". Installation, security, troubleshooting and maintenance are updated, and there are executed examples for the new commands.
- CI uploads the prompt pack as a second artefact.

Changed
- Help texts, usage guide and manual address "your AI agent" instead of one product.
- The packaged kit (`template/` inside an installed skill) can rebuild and validate its own skill without the repository.

## 1.4.0 - 2026-10-29

Added
- PDF manual `docs/akeyless-watchover-manual.pdf`, written in LaTeX (`docs/manual/`, built by `docs/manual/build.py`).
  - Contents: installation, quick start, workflow recipes, security considerations, troubleshooting/FAQ (every guard message), maintenance, exit codes, environment variables, glossary.
  - Every skill command comes with an example session. Every kit command lists all of its options and shows a real example execution.
  - Example executions run in a sandbox. Live commands run against a stand-in CLI/REST back end that answers from the test fixtures.
  - The command reference, the Terraform variables/outputs and the converted `docs/*.md` chapters are generated. A test checks they are current.
- `watchover forwarder` scaffolds new event forwarders, since Akeyless has no list operation to export them.
  - Types: email, webhook, slack, teams and service_now.
  - Events come from `--event` or presets (certificates, auth-methods, rotation, secrets, access-requests, operations, critical).
  - Input is checked against the same rules as the Terraform guards.
  - Output is a model entry (`--write` inserts it into governance.yaml and keeps comments; duplicate names are refused) or plain HCL (`--format hcl`).
  - `--import-existing` adopts a forwarder whose name you know.
  - Secrets are referenced as `*_var` keys and never written.
- The Terraform model supports `service_now` forwarders and webhook certificate auth (`client_cert_data_var`, `private_key_data_var`, `server_certificates_var`).
- New guards: a periodic runner needs `every`; slack/teams need `url_var`. Both are proven by fixtures.
- Test fixture `terraform/tests/fixtures/forwarders` is generated by the command, plans all 5 types, and is drift-checked by pytest.

Fixed
- Piping `watchover` output into `head` no longer ends with a BrokenPipeError traceback.
- `watchover conjur` exits with code 2 and a one-line error on an unreadable policy, as when run directly.
- `watchover export` prints "nothing matched the filters" instead of an empty count list.

## 1.3.0 - 2026-10-29

Added
- `docs/api-vs-cli.md`: the REST API and the CLI are two clients of the same operations (659 of 666 API request schemas come from the CLI command package). It explains how to choose between them and what each one adds.
- `watchover export --transport cli|api`. REST mode needs no CLI binary: it uses `--token` / `$AKEYLESS_TOKEN`, plus `--api` and `--gateway-api`.
- New export families: `targets`, `groups` and `gateway` (defaults, cache, remote access, log forwarding, migrations, allowed access), all written as plain Terraform with `--hcl`.
- Test fakes for the CLI and REST back ends. A test requires identical output from the CLI, REST and saved-JSON paths, and checks the exact CLI commands and REST request bodies.

## 1.2.0 - 2026-10-29

Added
- `watchover export` reads every exportable object family: roles, auth methods (all types), explicit folders, custom fields, key policies, PKI issuers and account settings.
- Model mode now translates type-specific auth method settings: OIDC (issuer, client ID, redirect URIs, scopes...), SAML, OAuth2/JWT, AWS IAM, Azure AD, K8s and Universal Identity. The field mapping comes from the provider's read code. Model mode also covers folders, custom fields and key policies.
- `--hcl` mode writes flat import blocks for every object. With `--generate` it runs `terraform plan -generate-config-out` so Terraform writes plain HCL itself. This includes PKI issuers, account settings and the GCP/LDAP/cert/OCI/AliCloud/Kerberos/email auth methods.
- Filters: `--types`, `--only`, `--exclude`, `--root`, `--max-depth`, and a persona view (`--persona-auth-method` plus `--persona-claim`) that exports one user's auth method and the roles they reach.
- Secrets are redacted in `raw/`, and `raw/` can be replayed offline with `--from-dir`.

Fixed
- `naming` prefixes are now disabled with `""`. `null` falls back to the default because of `optional(string, default)`, so the old documented way did not work. A test covers it.

## 1.1.0 - 2026-10-28

Added
- `scripts/watchover`: one entry point for every kit command (`test`, `simulate`, `verify`, `export`, `conjur`, `account-settings`, `token`, `build-skill`, `help`, `version`).
- `watchover help`: overview, per-command parameters and examples (`help <command>`), skill commands (`help skill`) and the full guide (`help --markdown`).
- Skill commands with a `help` command: `help`, `design`, `change`, `review`, `pipeline`, `import`, `conjur`, `pki`, `harden`, `gateway`, `verify`, `cli`, `explain`.
- `docs/usage-guide.md`, generated from `scripts/watchover.py`. Tests fail when the guide, SKILL.md or any parameter's help text drift from the code.

Changed
- Every script parameter now has a help text. Scripts expose `build_parser()` and `main(argv)`.

## 1.0.0 - 2026-10-28

First release as **akeyless-watchover**. It was previously drafted as `akeyless-governance-iac`.

Added: closes the gaps identified in the first review.
- Gateway admin plane: `gateway.yaml` -> `akeyless_gateway_allowed_access` (provider alias `akeyless.gateway`).
- SIEM log forwarding (syslog, splunk) and Conjur secret migration on the Gateway.
- CI identity bootstrap (`bootstrap/`): OAuth2/JWT auth method for GitHub or GitLab OIDC, separate plan and apply roles, separate state.
- GitHub Actions and GitLab CI templates with plan, apply, CLI account settings and nightly drift detection. CODEOWNERS example.
- Extended guards: naming prefixes, capabilities per rule type, SRA conflict, root scope, management-plane values, mandatory sub-claims, PKI consistency, event forwarders, gateway objects. Each one is proven by a fixture and by `guard_messages.sh`.
- Governance objects: account custom fields, key policies, event forwarders (email/webhook/slack/teams), account settings (Terraform subset plus the CLI-only part via `akl_account_settings.py`).
- Model-driven PKI: CA keys and issuers.
- Access verification: offline simulator (`akl_simulate.py`) and live verifier (`akl_verify.py`, uses `describe-permissions`).
- Brownfield exporter (`akl_export.py`): YAML model, import blocks and review report.
- Conjur policy translator (`conjur2akeyless.py`).
- Skill packaging (`build_skill.sh`) and repository CI on Terraform and OpenTofu.
- Full documentation in `docs/`.

Fixed:
- `describe-permissions` is documented correctly: it returns the caller's own permissions. The first draft described it as "who can access".
